# Contrato de integración: sólo simulación entregada
ChatwootPort: ensureConversation, send, reconcile, parseEvent, mapping. SimulatedChatwoot usa dos Accounts/inboxes ficticias distintas, claves lógicas, recibos durables y escenarios reproducibles. No llama HTTP. events valida Account/inbox antes de resolver conversación; no procesa cambios de estado como reanudaciones.
La demo no demuestra Chatwoot instalado ni su versión, API, autenticidad de webhooks o capacidades de entrega. No existe adaptador http.ts operativo, URL de integración aceptada por frontend ni webhook real expuesto.
Referencia de investigación: https://developers.chatwoot.com/api-reference/introduction . Application API (token servidor) y Platform API (provisionamiento autorizado) deben validarse en la instancia elegida antes del piloto. No se afirma idempotencia nativa ni soporte de firma.
Pendientes obligatorios para integración real: acceso autorizado/versión de instancia, permiso para Account dedicada por cliente, inbox/canal y mapeo servidor, endpoints y paginación exactos, credencial de servidor en almacenamiento aprobado, autenticación real del webhook, contrato de eventos/orden, semántica timeout/conciliación e idempotencia, barrera de pausa, límites temporales y pruebas sandbox. Si no se confirma autenticidad, sigue bloqueado.
WhatsApp/Meta: consentimiento, login, selección/verificación de activos, OTP donde corresponda y validación recepción/envío/pase; investigar elegibilidad Embedded Signup/coexistencia y compatibilidad Chatwoot. Sin conexión, token persistente ni envío real en este MVP.

## Inventario exacto del código entregado
- `packages/adapters/src/chatwoot/port.ts`: interfaz TypeScript; no transporte. Define ensureConversation, send, reconcile, parseEvent y mapping.
- `simulated.ts`: única implementación. Identifica mode simulated; fabrica identificadores Account/inbox/conversación, representa escenarios normal/transient/permanent/uncertain/unreconcilable y conserva recibos en PostgreSQL para deduplicar/conciliar. No usa fetch, cliente HTTP, SDK ni token Chatwoot.
- `events.ts`: procesador interno de eventos normalizados; verifica el mapeo servidor y deduplica, pausa ante actividad humana. No recibe ni autentica webhooks HTTP de Chatwoot real.
- Servicios de dominio dispatcher/recovery/pauses: orquestan envío simulado, outbox, conciliación y barrera humana. API y worker inyectan SimulatedChatwoot; handoff también llama ese mock.

**Código que conecta por API real: ninguno.** El contrato anterior describe requisitos pendientes, no una integración hecha. Falta implementar y validar adaptador HTTP de servidor contra instancia autorizada, mapeo real Account/inbox/contact/conversation, autenticación/secretos, recepción y autenticidad de webhooks, traducción de eventos, tratamiento de errores/timeout/conciliación/idempotencia, pruebas de contrato sandbox y pase humano real. WhatsApp requiere autorización y configuración separadas. No se configuró ni probó ninguno de esos servicios.
